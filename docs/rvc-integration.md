# Juliette TTS → RVC integration

## Scope

RVC is an optional post-processing stage for audio generated by TTS engines.
It does not capture or convert microphone audio. Loquendo remains a TTS
provider and must continue to work when RVC is disabled.

Expected flow:

1. The Discord Cog asks the selected TTS provider to synthesize text to WAV.
2. If an RVC model is selected, the Cog passes that WAV and the model ID to
   `rvc_adapter.convert_wav()`.
3. Juliette plays the converted WAV. If conversion fails, the caller should
   report the error and may fall back to the original TTS WAV only when the
   user has enabled fallback.
4. With no selected RVC model, play the original TTS WAV unchanged.

## Resource boundary

Do not run RVC inference inside the Wispbyte bot process. This adapter is a
small HTTP client; model loading and inference belong on a separate service
with suitable CPU/GPU resources. Keep the model weights out of this repository
and out of Wispbyte's limited disk unless explicitly needed.

## HTTP contract

Set `JULIETTE_RVC_URL` to an HTTPS URL for a trusted service endpoint. The
adapter sends a JSON POST:

```json
{
  "model": "kasane-teto-synthv-rvc-v2",
  "input_format": "wav",
  "audio_base64": "<base64 WAV bytes>"
}
```

The service must return HTTP 200 and JSON:

```json
{
  "audio_base64": "<base64 converted WAV bytes>"
}
```

Both input and output must be RIFF/WAVE. The endpoint and model weights are
not bundled here; no hosted inference service is provisioned by this change.
Never send private audio or text to an untrusted endpoint.

## Initial model catalog

`rvc_models.json` registers Kasane Teto (SynthV), RVC v2, Japanese, 500
epochs as the first candidate. The entry is disabled until the model weights
are installed on the inference service and tested. The catalog entry does not
redistribute the model.

## Bot integration still required

The main Discord Cog (`loquendo.py`) is not in this repository. Its command
layer should expose one central `/fakevoice` control group for:
- selecting a TTS provider (including Loquendo);
- listing/selecting installed RVC models;
- enabling/disabling the RVC post-processing stage;
- showing whether the remote service is configured.

Keep existing commands such as `/tts`, `/voices`, `/voice`, `/join`,
`/leave`, and automatic channel reading compatible. Do not make RVC
mandatory for normal TTS playback.
